# 미장 단타 자동매매 시스템 — 개발 명세서

> **이 문서의 목적**: LLM(또는 개발자)이 이 문서만 읽고 전체 시스템을 단계적으로 구현할 수 있도록 설계 의도, 데이터 흐름, 기술 스택, 구현 순서를 모두 담았다.

---

## 1. 시스템 철학

이 시스템은 **"뉴스를 읽는 시스템이 아니라, 뉴스가 나올 것을 예측하는 시스템"**이다.

기존 방식(뉴스 감지 → 테마 파악 → 종목 선정 → 매수)은 이미 늦다. 뉴스가 나오면 세력은 이미 빠져나가는 중이다.

이 시스템은 3개의 레이어로 작동한다:

- **Layer 1 — 국제정세/매크로 (방향)**: 가장 느리지만 가장 강력. 전쟁, 금리, 무역분쟁, 원자재 공급 등을 통해 어느 섹터가 수혜인지 판단한다.
- **Layer 2 — 스마트머니 감지 (타이밍)**: 정세를 아는 세력이 먼저 포지션을 잡는 흔적을 추적한다. 옵션 이상거래, 다크풀 거래량 급증, 공매도 잔량 급감, 의원 주식거래, 내부자 매수 등.
- **Layer 3 — 차트/거래량 (확인)**: 세력 매집 패턴이 실제로 존재하는지 기술적으로 확인한다.

**세 레이어가 동시에 정렬될 때만 진입한다.**

뉴스가 나오면 매수가 아니라 **청산 판단 시점**으로 활용한다.

---

## 2. 전체 파이프라인 아키텍처

```
[Phase 0] 로직체인 DB 구축 (독립 선행 작업, 1회성 + 지속 보강)
    ↓
[Phase 1] 실시간 파이프라인 가동
    ↓
┌─────────────────────────────────────────────────────┐
│  STEP 1. 선행 데이터 수집 (스마트머니 + 매크로)       │
│  STEP 2. AI 역추론 (이상 신호 → 원인 추론)           │
│  STEP 3. 종목 1차 필터링                             │
│  STEP 4. 차트 세력 흔적 스코어링                      │
│  STEP 5. 통합 스코어링 & 최종 추천                    │
│  STEP 6. 포지션 관리 & 청산 판단                      │
└─────────────────────────────────────────────────────┘
    ↓
[Phase 2] 피드백 루프 (로직체인 성과 기록 → 가중치 조정)
```

## 3. Phase 0 — 로직체인 DB 구축

> **이 단계는 나머지 파이프라인과 독립적으로 먼저 수행해야 한다.**
> 로직체인 DB가 없으면 Step 2(역추론)와 Step 5(스코어링)가 작동하지 않는다.

### 3.1 로직체인이란

매크로 이벤트와 수혜/피해 섹터 간의 인과관계 지식 베이스다.

예시:
- 금리인상 → 달러강세 → 금값하락 → 금광주 약세 / 은행주 강세
- 중동긴장 → 유가상승 → 에너지주 강세 / 항공주 약세
- 반도체수출규제 → 미국 반도체장비주 강세

### 3.2 데이터 구조

각 로직체인은 아래 JSON 스키마를 따른다:

```json
{
  "chain_id": "LC-001",
  "event": "금리인하 시사",
  "causal_path": "금리인하 → 유동성확대 → 성장주 자금유입",
  "beneficiary_sectors": ["성장주", "리츠", "기술주"],
  "victim_sectors": ["은행주", "보험주"],
  "intensity": "high",
  "time_horizon": "1~3일",
  "reaction_speed": "즉각반응",
  "pre_signals": [
    "국채수익률 하락 시작",
    "달러인덱스 약세 전환",
    "금 선물 거래량 급증",
    "Fed 인사 발언 톤 변화"
  ],
  "historical_accuracy": null,
  "created_at": "2026-03-16",
  "source": "claude_generated"
}
```

필드 설명:
- `chain_id`: 고유 식별자
- `event`: 트리거 이벤트명
- `causal_path`: 인과 경로를 화살표로 표현
- `beneficiary_sectors`: 수혜 섹터 리스트
- `victim_sectors`: 피해 섹터 리스트
- `intensity`: 영향 강도 (high / medium / low)
- `time_horizon`: 효과 발현 시간 (즉각 / 1~3일 / 1주일+)
- `reaction_speed`: 단타 목적이므로 "즉각반응" 체인에 가중치 부여
- `pre_signals`: **핵심 필드**. 이 이벤트가 터지기 전에 나타나는 선행 징후 리스트. Step 2의 역추론에서 이 필드를 역방향 검색한다.
- `historical_accuracy`: 피드백 루프에서 기록되는 실제 적중률 (초기에는 null)
- `source`: 생성 출처 (claude_generated / manual / news_derived)

### 3.3 초기 구축 방법

1. Claude API에 프롬프트를 보내 초기 체인 300~500개를 생성한다.
2. 생성 시 아래 카테고리별로 균등하게 분배한다:
   - 금리/통화정책 (50개+)
   - 지정학/전쟁 (50개+)
   - 무역/관세 (50개+)
   - 원자재/에너지 (50개+)
   - 기술/규제 (50개+)
   - 실적/어닝시즌 (50개+)
3. 각 체인을 Embedding 모델(all-MiniLM-L6-v2 등)로 벡터화한다.
4. ChromaDB(로컬)에 저장한다.

### 3.4 구축용 프롬프트 예시

```
당신은 미국 주식시장 매크로 분석 전문가입니다.
아래 형식의 JSON으로 로직체인을 생성하세요.

카테고리: 금리/통화정책
조건:
- 미국 주식시장 기준
- 각 체인에 반드시 pre_signals(선행 징후) 3~5개를 포함할 것
- reaction_speed는 "즉각반응", "1~3일", "1주일+" 중 택1
- 단타 매매에 활용할 것이므로 즉각반응 체인을 우선 생성

50개를 생성하세요.
```

### 3.5 지속 보강

- 실시간 파이프라인 가동 후 Step 2에서 기존 체인과 매칭 실패한 이벤트가 발생하면, Claude API가 신규 체인을 생성하여 DB에 추가한다.
- Phase 2(피드백 루프)에서 적중률이 낮은 체인은 가중치를 하향한다.

### 3.6 기술 스택 (Phase 0)

| 구성 요소 | 도구 | 비고 |
|-----------|------|------|
| 체인 생성 | Claude API (Sonnet 4.5) | Batch API 사용 시 50% 할인 |
| 임베딩 | sentence-transformers (all-MiniLM-L6-v2) | 로컬, CPU 가능 |
| 벡터 DB | ChromaDB | 로컬, 무료 |
| 저장 포맷 | JSON + ChromaDB | 원본 JSON 파일도 별도 보관 |

### STEP 2. AI 역추론

> **"왜 이 움직임이 나왔는가"를 역으로 추론하는 핵심 단계**

#### 2-1. 흐름

```
이상 신호 감지 (Step 1에서 수집)
    ↓
Claude API에 전달: "이런 패턴이 과거에 어떤 이벤트 직전에 나왔었나?"
    ↓
가능한 원인 후보 리스트 생성 (시나리오 A, B, C...)
    ↓
각 시나리오를 로직체인 DB에서 역방향 검색
  (pre_signals 필드와 현재 이상 신호를 벡터 유사도 매칭)
    ↓
매칭된 로직체인의 beneficiary_sectors에서 수혜 종목 도출
    ↓
매칭 실패 시 → Claude가 신규 로직체인 생성 후 DB에 추가
```

#### 2-2. Claude API 호출 예시

```json
{
  "model": "claude-sonnet-4-5-20250514",
  "messages": [
    {
      "role": "user",
      "content": "다음 이상 신호들이 동시에 감지되었습니다:\n1. NVDA 콜옵션 이상 거래 ($250만 프리미엄)\n2. SMH(반도체 ETF) 다크풀 거래량 전주 대비 300% 급증\n3. 달러인덱스 0.5% 급락\n\n이 조합이 과거에 어떤 이벤트 직전에 나타났었는지 분석하고, 가능성 높은 시나리오 3개와 각 시나리오별 수혜 섹터를 JSON으로 반환하세요."
    }
  ]
}
```

#### 2-3. 벡터 유사도 검색

```python
# 현재 이상 신호들을 텍스트로 변환
current_signals = "국채수익률 하락, 달러인덱스 약세, 금 선물 거래량 급증"

# ChromaDB에서 pre_signals 필드 기반 유사도 검색
results = collection.query(
    query_texts=[current_signals],
    n_results=5,
    where={"reaction_speed": "즉각반응"}  # 단타 우선
)
```

### STEP 3. 종목 1차 필터링

> **테마 내에서 "지금 당장 움직일" 종목 추리기**

#### 3-1. 필터 조건

| 조건 | 기준 | 이유 |
|------|------|------|
| 시가총액 | $500M ~ $10B | 중소~중대형. 대형주는 변동성 부족, 소형주는 유동성 리스크 |
| 거래량 | 최근 20일 평균 대비 150%+ 급증 | 세력 유입 신호 |
| 공매도 비율 | 낮을수록 가산점 | 숏커버링 리스크 낮음 |
| 옵션 Put/Call Ratio | 낮을수록 가산점 | 콜 우세 = 상승 기대 |
| 내부자 매수 | 최근 3일 내 공시 있으면 가산점 | CEO/CFO 매수는 강력한 신호 |
| 어닝 발표 임박 | 조건부 포함 | 단타엔 리스크, 하지만 서프라이즈 기대 시 포함 |

#### 3-2. 추가 필터

- 섹터 ETF 자금흐름 확인: XLE, SMH, XLF 등 ETF 수급이 개별주보다 먼저 움직인다.
- 유사 과거 이벤트에서 실제로 올랐던 종목 히스토리 참조 (피드백 루프 데이터 활용).

#### 3-3. 데이터 소스

| 데이터 | 소스 |
|--------|------|
| 주가/OHLCV | Alpaca API (무료 계정) |
| 시가총액/스크리너 | Finnhub 무료 |
| SEC 공시 | SEC EDGAR RSS |
| 어닝 캘린더 | Finnhub |

### STEP 4. 차트 세력 흔적 스코어링

> **타이밍 관점의 기술적 분석. "매수 적합한 차트인가?"**

#### 4-1. 세력 흔적 패턴 (점수화)

| 패턴 | 의미 | 점수 |
|------|------|------|
| 저거래량 횡보 후 거래량 폭발 | 세력 매집 완료 신호 | +5 |
| 갭다운 후 빠른 회복 | 개인 투매를 세력이 받아감 | +4 |
| 52주 박스권 상단 반복 터치 | 돌파 임박 | +4 |
| 호가창 매도벽 소멸 | 세력이 물량 소화 완료 | +3 |
| 일봉 아랫꼬리 연속 출현 | 저가 매집 패턴 | +3 |

#### 4-2. 기술적 지표

| 지표 | 조건 | 점수 |
|------|------|------|
| VWAP | 현재가 > VWAP | +2 |
| RSI(14) | 40~60 구간 (과매수 아닌 눌림목) | +2 |
| 볼린저밴드 | 수축 후 확장 초기 | +3 |
| 52주 고점 돌파 시도 | 고점 대비 95% 이내 | +2 |
| 갭업 후 첫 눌림 | 갭업 당일~익일 눌림 구간 | +3 |

#### 4-3. 멀티 타임프레임

1분/5분/15분/일봉을 동시에 확인한다. 상위 타임프레임(일봉)에서 상승 추세이면서 하위 타임프레임(5분)에서 눌림목 진입 포인트가 나올 때 최적.

#### 4-4. 기술 스택

| 구성 요소 | 도구 |
|-----------|------|
| OHLCV 데이터 | Alpaca API |
| 기술 지표 계산 | TA-Lib 또는 pandas-ta (로컬, 무료) |
| 패턴 인식 | 코드 기반 룰 엔진 |

### STEP 5. 통합 스코어링 & 최종 추천

> **전 단계 신호를 종합하여 최종 매수 우선순위 결정**

#### 5-1. 스코어링 테이블

| 항목 | 배점 | 산출 방식 |
|------|------|-----------|
| 로직체인 매칭 강도 | 30점 | 벡터 유사도 점수 × 체인 intensity × historical_accuracy |
| 스마트머니 시그널 | 20점 | 옵션 이상거래 + 다크풀 + 내부자/의원 거래 복합 점수 |
| 거래량/수급 신호 | 20점 | 거래량 급증률 + 섹터 ETF 자금흐름 |
| 차트 기술적 스코어 | 20점 | Step 4의 패턴 점수 + 기술적 지표 점수 합산 |
| **VIX 가산점** | **+10점** | 아래 테이블 참조 |
| 리스크 패널티 | -10점 | 이미 30%+ 급등 / 어닝 직전 불확실성 등 |

#### 5-2. VIX 가산점

VIX(공포지수)가 높을수록 단타에 유리한 환경이다. 변동성 극대화 = 과매도 반등 기회 풍부.

| VIX 범위 | 가산점 | 해석 |
|----------|--------|------|
| 20 이하 | +0점 | 평시. 표준 기준으로 운영 |
| 20 ~ 30 | +3점 | 긴장 시작. 기회 확대 |
| 30 ~ 50 | +7점 | 공포 구간. 단타 황금기 |
| 50 이상 | +10점 | 극공포. 역사적으로 저점 근처 |

VIX 데이터는 Yahoo Finance 또는 FRED에서 무료로 수집한다.

> **기존 설계의 "VIX 30 이상이면 시스템 중단" 조건은 완전히 삭제되었다.**

### STEP 6. 포지션 관리 & 청산 판단

#### 6-1. 리스크 게이트

| 조건 | 행동 |
|------|------|
| 해당 종목 최근 30%+ 급등 | 진입 제외 |
| 켈리 공식 기반 베팅 사이즈 | 종목별 자동 계산 |
| 동시 최대 보유 종목수 | 3~5개 제한 |
| 동일 테마 몰빵 방지 | AI로 포트폴리오 내 상관관계 체크 |

#### 6-2. 뉴스 출현 시 판단 분기

```
뉴스 출현
    ↓
이미 선진입 했나?
    ├── YES → 익절 타이밍 계산 (뉴스 = 청산 시그널)
    └── NO  → 이미 반영됐나 차트 확인
                  ├── 급등 완료 → 패스
                  └── 아직 안 올랐다면 → 2차 파동 가능성 판단 후 진입 검토
```

#### 6-3. 실시간 청산 로직

| 조건 | 행동 |
|------|------|
| 뉴스 역전 감지 (호재→악재) | 즉시 청산 |
| 목표가 도달 | 익절 |
| 손절가 도달 | 손절 |
| Trailing Stop | 고점 대비 N% 하락 시 자동 청산 |

#### 6-4. 브로커 연동

| 용도 | 도구 |
|------|------|
| POC / 백테스트 | Alpaca 페이퍼 트레이딩 (무료) |
| 실전 매매 | Alpaca 실계좌 (수수료 무료) 또는 Interactive Brokers API |

## 5. Phase 2 — 피드백 루프

### 5-1. 로직체인 성과 추적

매 트레이드 종료 시 아래를 기록한다:

```json
{
  "trade_id": "T-20260316-001",
  "logic_chain_id": "LC-042",
  "ticker": "NVDA",
  "entry_price": 940,
  "exit_price": 975,
  "pnl_percent": 3.72,
  "vix_at_entry": 35,
  "entry_score": 82,
  "result": "profit",
  "duration_minutes": 180,
  "exit_reason": "target_reached"
}
```

### 5-2. 가중치 조정

- 각 로직체인별 적중률(수익 트레이드 / 전체 트레이드)을 계산한다.
- 적중률이 낮은 체인은 `historical_accuracy`를 하향 → Step 5 스코어링에서 자연스럽게 점수가 낮아진다.
- 적중률이 높은 체인은 가중치 상향.
- Claude API로 "왜 틀렸는지" 사후 분석 리포트를 생성한다.

### 5-3. VIX 모드별 성과 추적

VIX 구간별로 트레이드 성과를 분리 집계한다. "VIX 30~50 구간에서의 평균 수익률"이 쌓이면 VIX 가산점 테이블을 더 정밀하게 튜닝할 수 있다.

## 10. 핵심 주의사항

1. **로직체인 DB 품질이 전체 성능을 좌우한다.** 초기 생성 시 충분한 검토와 정제가 필요하다. 쓰레기 체인이 들어가면 역추론 결과도 쓰레기가 된다.

2. **뉴스는 매수 트리거가 아니라 청산/2차파동 판단용이다.** 이 패러다임을 코드 구조에 명확히 반영해야 한다. 뉴스 모듈이 매수 신호를 발생시키면 안 된다.

3. **VIX는 높을수록 좋다.** 기존 설계의 "VIX 30 이상 시스템 중단"은 삭제되었다. VIX가 높을수록 가산점이 올라간다.

4. **3-Layer 동시 정렬이 진입 핵심이다.** 각 레이어의 신호를 독립 모듈로 만들어야 조합과 테스트가 쉬워진다.

5. **피드백 루프를 초기부터 넣어야 한다.** 로직체인 성과 기록 없이 실전에 들어가면 어떤 체인이 유효하고 어떤 게 노이즈인지 알 수 없다.

6. **Phase 0(로직체인 DB)를 반드시 먼저 완성하고 나서 Phase 1(실시간 파이프라인)에 들어간다.** 이 두 단계는 의존 관계가 있다.
