## 4. 시스템 구조

### 4-1. 6 역할 (전부 Claude Opus 4.7, system prompt만 다름)

| 역할 | 책임 | temperature |
|---|---|---|
| 진행자 | 어젠다 발행, 라운드 요약, 종료 판정 | 0.3 |
| 데이터 제공자 | 시세·공시·뉴스 수집 | 0.0 |
| 검수자 | 데이터 검수, 룰 강제, 반려권 | 0.0 |
| 토론자 Bull | 매수 시나리오, 업사이드 | 0.9 |
| 토론자 Bear | 무효화 조건, 다운사이드 | 0.7 |
| 토론자 Quant | 수치 중재, 통계 검증 | 0.4 |

다양성은 **모델이 아니라 페르소나 .md의 깊이**에서 나옴. 각 페르소나에 (a) 손익함수 (b) 금기 (c) 발언 톤 (d) few-shot 3개를 박는다.

### 4-2. 토론 흐름

```
어젠다 발행 (진행자)
   ↓
데이터 수집 (데이터 제공자) → yfinance, SEC EDGAR, CoinGecko
   ↓
검수 통과 (검수자) — 반려 시 재수집 (최대 K회)
   ↓
[토론 N라운드 × 발언권 M회]
   Bull → Bear → Quant 순서, 이전 발언 @인용 강제
   ↓
종료 판정 (진행자)
   consensus / disagree / stalled / max_rounds
   ↓
트랜스크립트 JSON 저장 (storage/runs/)
```

### 4-3. 옵셔널 제약 (`config.yml`)
- 발언권: 토론자당 **3회**
- 최대 라운드: **5**
- 발언 길이: **280자** (Alpha Arena 톤)
- @인용 강제 (병렬 독백 방지)

## 5. 기술 스택

| 레이어 | 기술 |
|---|---|
| 언어 | Python 3.11+ |
| LLM 호출 | Claude Code CLI 헤드리스 (`claude -p`) |
| **추상화** | `LLMRunner` Protocol — CLI ↔ API swap 가능 |
| 저장 | SQLite (트랜스크립트) |
| 스케줄 | APScheduler 또는 cron |
| 웹 (Phase 7) | FastAPI + Next.js |

### 핵심: LLM 호출 추상화 = 매각 안전장치
```python
class LLMRunner(Protocol):
    async def call(self, system, user, **kw) -> LLMResponse: ...

class ClaudeCodeCLIRunner: ...   # 지금
class AnthropicAPIRunner: ...    # 매수자가 1줄로 swap
```
모든 LLM 호출은 이 함수 하나만 통과. `config.yml`의 `runner: claude_cli | anthropic_api`.

## 7. 운영 모델

- **인증**: 매수자가 `claude login` 1회 → 끝
- **함정**: `ANTHROPIC_API_KEY` env var는 무조건 제거 (있으면 구독 무시하고 API 결제됨)
- **빈도**: 7토론/일 (Claude Max 5시간당 한도 내)
  - BTC 4h봉 마감 × 2
  - 미장 개시·정오·마감 × 3
  - 매크로 이벤트 × 1~2
- **월 비용**: $200 (Claude Max) + $1 (도메인) = **~$201**

## 9. Phase 계획 (8주)

| 주차 | Phase | 산출물 |
|---|---|---|
| 1 | 스캐폴드 | 폴더 구조, README들, JSON 스키마, config.yml |
| 2 | LLM 추상화 | `claude -p` 호출 작동 + 토큰·비용 파싱 |
